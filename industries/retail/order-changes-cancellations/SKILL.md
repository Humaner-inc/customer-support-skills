# Retail -- Order Changes and Cancellations

## When to use

The customer wants to cancel an order, change items, update quantity, switch shipping method, or edit an address after placing the order.

## Procedure

### 1. Clarify the request

Confirm whether they want a full cancel, a partial cancel, an item swap, a quantity change, or a shipping update. These have different eligibility windows.

### 2. Pull the order and check status

Look up the order in the knowledge base. Key branch:

- **Not yet shipped / still processing:** changes are often possible. Follow the edit or cancel path in the knowledge base.
- **Already shipped:** cancel is usually not possible. Offer return after delivery, or carrier intercept only if the knowledge base supports it.
- **Partially shipped:** cancel or edit only the unshipped portion.

### 3. Apply the knowledge base rules

Share what is and is not allowed for this order status. Include any fees, restocking rules, or refund timing only if documented.

### 4. Execute or guide self-serve

If the knowledge base allows agent-side cancel or edit, do it and confirm. Otherwise guide the customer to the account order page or portal steps.

### 5. Confirm outcome

State clearly: what changed, refund method and timeline (from KB), whether they need to refuse delivery or initiate a return later.

## What not to do

- Do not cancel a shipped order as if it were unshipped.
- Do not invent cancellation deadlines or restocking fees.
- Do not promise carrier intercept unless the knowledge base says it is available.
- Do not leave the customer unsure whether money is coming back and when.
